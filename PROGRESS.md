## 1. Цель и состояние

Самостоятельный локальный настольный питомец для Windows по принципу Desktop Goose. Персонаж — сиба-ину Кайфик, нарисованный по фотографиям собаки пользователя. Приложение не требует ChatGPT или сети во время работы.

## 4. Технологии и средства сборки

C# 7.3, WinForms + P/Invoke Win32, .NET Framework 4.8, x64, классический non-SDK csproj. Внешних NuGet-пакетов нет. Не нужны Python или отдельный игровой движок для основного приложения.

Аудит 18 октября обнаружил Visual Studio Community 2022 17.14.15, VS MSBuild 17.14.23, Roslyn 4.14 и targeting pack Framework 4.8. VS не обязательно открывать.

Текущий build.ps1 использует жёсткий путь:

`C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe`

Framework runtime: Version 4.8.09221, Release 533509. Резервный Framework csc существует в `C:\Windows\Microsoft.NET\Framework64\v4.0.30319`, но поддерживает старый C# и не является основным способом сборки. На момент аудита `dotnet --list-sdks` пуст; runtimes NETCore 6/8 и WindowsDesktop 6 сами по себе SDK не заменяют. Доступны Git, Node/npm, Python для вспомогательных работ. Проверять среду заново на другом ПК.

Сборка в PowerShell из корня:

```powershell
.\build.ps1 -OutputDirectory 'dist\Alpha-drag' -SettingsSourceDirectory 'dist\Alpha-drag'
```

Не перезаписывать запущенный EXE; при необходимости выбрать новую папку результата. Скрипт копирует выбранные клипы и 8 сидячих взглядов из Frames, создаёт отдельный манифест поставки и копирует meme-scales.json. Исходный Frames не меняется. ВАЖНО: build.ps1 не копирует сами мемы; действующий конфиг MemeSourceDirectory на ПК пользователя указывает на абсолютную исходную папку. Перед запуском клона на другом ПК проверить/адаптировать этот путь в `<поставка>/data/settings.json` и при необходимости упаковку мемов. Файлы уже есть в репозитории в Frames/memes, не нужно получать их извне.

## 5. Архитектура кода

- `Program.cs` — STA, один экземпляр, запуск, диагностические аргументы.
- `PetApplicationContext.cs` — жизненный цикл, один UI-цикл, связи поведения/отрисовки/ввода, трей и окно управления.
- `UI/PetWindow.cs` — layered/no-activate окно, hit testing по альфе, клики/capture.
- `UI/PetPointerGesture.cs` — различение потенциального клика и drag по системному порогу.
- `UI/ControlWindow.cs` — окно управления и кнопка на панели задач, ручные действия, очередь/skip.
- `Animation/AssetCatalog.cs` — загрузка, валидация, индексы кадров и якоря.
- `Behavior/BasicBehaviorController.cs` — спокойные Idle/Walking, движение по области.
- `Behavior/InteractionController.cs` — сценарии, таймер спокойного времени, ручные/автоматические старты.
- `Behavior/InteractionQueue.cs` — очередь случайных действий и ограничение повторов.
- `Behavior/CursorInteraction.cs`, `WatchInteraction.cs`, `MemeInteraction.cs` — сложные сценарии.
- `Behavior/MemeQueue.cs` — отдельная очередь изображений.
- `Platform/MemeWindowHost.cs` — собственные WinForms-окна мемов, PictureBox Zoom; НЕ Microsoft Photos.
- `Platform/CursorAdapter.cs`, `DesktopAreaService.cs`, `NativeMethods.cs` — системные адаптеры.
- `Infrastructure/SettingsStore.cs` — настройки/миграции/диагностика.
- `*Tests.cs`, `*UiTest.cs` в src — встроенные проверки; результаты в tests/results.

Изображения рендерятся через UpdateLayeredWindow с попиксельной альфой; освобождать Bitmap/HBITMAP/DC и capture. Положение и кадры считаются по активному времени, не по количеству тиков. Не выполнять старые `next` или `sleep_trigger` из исходного JSON как бизнес-логику без учёта сценария: runtime управляет переходами явно.

## 6. Текущее поведение

На каждом обычном старте Кайфик появляется в центре рабочей области основного монитора и сразу гуляет. Движется по всей области, в том числе диагонально; ходит 3–7 секунд, стоит 2–7 секунд. Границы отражают направление, питомец не выходит под панель задач. Отображение уменьшено до 2/3 исходного размера; PNG остаются 192×208. Пока движения в 8 направлениях используют боковые спрайты; новые ракурсы — задача беты.

Есть трей и отдельное окно «Кайфик — управление» с кнопкой панели задач. Прозрачный питомец не активирует чужой фокус. Пауза/скрытие замораживают прогресс, окно управления позволяет вернуть питомца, вручную запустить действия, увидеть очередь и выйти.

Спокойное время = сумма активного Idle+Walking, а не отсутствие ввода пользователя на ПК. Через настраиваемые 10 секунд запускается действие из случайной очереди. Во время интерактива/паузы/скрытия этот таймер не идёт; после завершения сбрасывается.

| № | Интерактив | Правила |
| --- | --- | --- |
| 1 | Сон | lie-down → sleep 60 секунд по умолчанию → wake-up; короткий клик в sleep будит раньше |
| 2 | Принести мем | Уйти за край, создать собственное окно, grab/pull/release с привязкой к пасти, оставить окно видимым |
| 3 | Погоня/перенос курсора | Chase → grab → attach → pull → release; полный успешный сценарий 15 активных секунд; Escape немедленно освобождает |
| 4 | Погоня за хвостом | chase-tail, первоначально 3 цикла |
| 5 | Потянуться и зевнуть | stretch-yawn, один проход |
| 6 | Почесаться за ухом | sit-down → enter → scratch 4 цикла → exit → stand-up |
| 7 | Сесть рядом и наблюдать | Подход → sit-down → направленный взгляд на курсор → stand-up; полный сценарий 20 активных секунд |

15/20 секунд включают подход и переходы; резервировать время выхода. Отмены/ошибки могут завершить раньше. Курсор при Watch только читается. Не подставлять фронтальную watch-idle ради моргания: это уже вызывало визуальный дефект, исправлено статичными направленными позами.

Очередь действий: 12 позиций, случайный выбор, не более двух одинаковых подряд, включая refill и ручные старты. Это НЕ shuffled bag: двойные повторы разрешены. «Пропустить действие» удаляет первое предстоящее, дополняет конец, активное не отменяет. Пропуск не записывается как выполнение. На старте включать все доступные 7 действий ДО первого наполнения: ранний баг заполнял 12 позиций без Meme. Исправлен. При смене доступности перестраивать хвост корректно. Чистый рандом не гарантирует мем за 5 минут; автоматическая доставка проверялась отдельным тестом.

Курсор освобождать при Escape, паузе, скрытии, ошибке, потере активной сессии и выходе. Не возвращать его скачком в старую позицию. Постоянных hooks/ClipCursor нет; Escape-hotkey временная.

Поглаживание: короткий левый клик по видимому силуэту только в calm Idle/Walking, движение останавливается, petting один раз → Idle, новый спокойный интервал. Не входит в случайную очередь. Повторные клики не перезапускают.

Перетаскивание: mouse-down сохраняет снимок/offset и capture, порог SystemInformation.DragSize отличает drag от короткого клика. Pending жест замораживает планировщик. Drag отменяет текущее разрешённое действие и играет dragged; отпускание/потеря capture → свежий Idle/calm=0. Запрещено во ВСЕХ фазах Cursor и Meme. Остальные действия, включая сон и поглаживание, отменять можно. Очередь сохраняется. На паузе можно вручную перемещать, сохраняя паузу. Не оставлять capture после cancel/hide/выхода.

## 7. Графика, якоря и мемы

Исходный набор Frames: 199 PNG RGBA 192×208, 30 анимаций и 24 направления взгляда (16 стоя + 8 сидя). Последняя альфа пакует подмножество: 24 клипа + 8 взглядов = 148 PNG, плюс мемы отдельно в исходной папке. Манифест содержит порядок/длительности, anchors, `mouth_anchors_px`, attach/detach frame_events. Масштабировать координаты пасти вместе с изображением/DPI; окно и курсор привязывать к ним, не к центру кадра.

`running` — историческое имя сидячего размышления, НЕ бег. `dragged` — самого Кайфика держат, НЕ перенос предмета. walk-v2 исправлял повтор задней лапы, но пользователь всё ещё просит исправить задние лапы в бете. Кадры зеркального переноса допустимы; художественная проверка важнее одной технической валидации.

Источник мемов: `Frames/memes`, без рекурсии. Отдельная очередь без одинаковых соседних файлов, в том числе на пополнении/после ручного запуска. При одном файле после первого повтор заблокирован до изменения доступного набора, при нуле действие недоступно. Своё окно не должно воровать фокус, закрытие картинки пользователем корректно отменяет перенос. Ошибки/отмена не должны оставлять окно невидимым за краем.

## 8. Проверки и реальные ограничения

По отчётам чата «Код» сборки Release/net48/x64 проходили self-test, UI smoke по 75 секунд, отдельные petting/drag/native HWND тесты и полный auto-meme путь на настоящем собственном окне. Последний отчёт — раздел перетаскивания в ALPHA-REPORT/contextproject; свидетельства `tests/results/drag`.

Проверены очереди на длинных сериях, таймеры 20/15 секунд, якоря, границы, нативный capture/hit-test/пары DOWN/UP, очистка ресурсов, отсутствие самопроизвольной активации. Auto-meme тест проходит обычный планировщик с изолированным seed/интервалом, а не ручной Start. Это не гарантия художественной плавности и пользовательского сценария на каждом ПК.

Аппаратное перетаскивание реальной мышью, её реальный захват, смена мониторов/DPI и некоторые проверки прозрачности со сторонним приложением не были полноценно выполнены. Не выдавать подставной cursor adapter и сообщения HWND за реальную пользовательскую мышь. GDI/USER проверялись короткими прогонами, длительная стабильность требует оценки. В errors.log встречаются намеренные fake-open/broken JSON ошибки тестов — не считать их автоматически runtime-багом.

Диагностические аргументы перечислены в Program.cs: изучить перед запуском. Self-test можно запускать с ожиданием процесса, UI smoke открывает реальные окна и завершается сам. Не запускать одновременно UI-тесты capture; закрывать только свои тестовые процессы, пользовательский экземпляр без поручения не завершать.
